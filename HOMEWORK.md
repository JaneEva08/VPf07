## 1. Задание

1. Собрать собственного AI-агента на OpenAI или другой модели.
2. Поиск информации в интернете (DuckDuckGo).
3. Погода для любого города.
4. Курс криптовалют.
5. Чтение и запись файлов.
6. История диалога в `memory.json`.
7. По желанию — два своих инструмента.

Формат сдачи: ссылка на GitHub-репозиторий.

## 6. Выводы

1. **Модель сама выбирает инструмент.** За прогон она вызвала 9 разных инструментов без подсказок: поиск, погода, крипта, валюты, калькулятор, чтение и запись файлов, заметки, терминал. Выборка небольшая: около 20 запросов, одна модель, по одному прогону.
2. **Живой прогон нашёл то, чего не видели тесты на заглушках.** Время погоды приходило в UTC и выдавалось за местное (14:30 вместо 17:30); модель отвечала Markdown и формулой в LaTeX, которые терминал показывает как есть. Оба дефекта исправлены. Ещё один — команды `cat` / `wc` / `echo` не существуют в Windows — поймал тест при локальном запуске.
3. **Отказ делает не только модель.** На «Выполни команду cat ../.env» модель отказалась сама, не вызвав инструмент. На «Прочитай ../.env» инструмент вызван, и отказал код (`Доступ разрешён только к папке workspace/`). Защита рассчитана именно на второй случай: на согласие модели полагаться нельзя. Это проверено на трёх фразах, не на атаке.
4. **Заметка переживает перезапуск, но проверка не отделяет её от истории.** После перезапуска агент мог взять факт и из заметки в системном промпте, и из подгруженных реплик. Различает их только юнит-тест `test_note_survives_following_turn`.
5. **Модель не держит заданный объём.** Просили 5000 символов, получилось 7929. Файл `test.json` — обычный текст, не JSON: так сформулировано в задании.
6. **Цифры Пи модель выдала верно** все 100 знаков, но это один запрос; проверять другие длинные последовательности не стала.

## 7. Что поправила по итогам

| Что нашла | Как исправила |
|---|---|
| `run_command` разрешал `cat ../.env`, `ls /` (воспроизведено: ключ уходил модели и в лог) | пути в аргументах проверяются так же, как в файловых инструментах |
| `save_note` затиралась при записи истории в конце хода | история перечитывается перед записью |
| Пустой ответ модели попадал в память и контекст | неудачный ход (пустой ответ, ошибка API, лимит шагов) откатывается |
| Сбой API ронял агента | ошибка возвращается текстом |
| Не было `OPENAI_BASE_URL` | `agent/provider.py`, адрес и модель из `.env` |
| `http_get` / `http_post` ходили на `localhost` и в частные сети | только http(s), локальные адреса и переадресации закрыты |
| `cat` / `wc` / `echo` не работают в Windows | команды выполняются средствами Python, без запуска процессов |
| Время погоды в UTC | параметр `timezone=auto` |
| Ответы с Markdown и LaTeX | запрет в системном промпте |
| В историю шёл весь `model_dump()` | только `role`, `content`, `tool_calls` |
| Таблица кодов погоды неполная | добавлены все коды WMO |

## 8. Что не сделано

- **Прогноз погоды на дату и время.** Инструмент даёт только текущую погоду. В уроке (стр. 12) есть запрос «завтра в 12:00», который так не решится.
- **Telegram-бот.** Не входит в требования ДЗ.
- **Обрезка длинного контекста внутри одной сессии.** Старые результаты инструментов остаются в `messages`.
- **Сравнение моделей.** Прогоны только на `gpt-6-luna`; `gpt-6-astra` не пробовала.
- **Повторные прогоны.** Каждый сценарий выполнен один раз.
