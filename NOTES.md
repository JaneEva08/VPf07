## Разбор урока

1. **О чём урок.**
   - LLM — предсказатель текста; агент = LLM + инструменты + память + цикл «решаю — делаю — оцениваю» (стр. 2–6).
   - Практика: терминальный агент на OpenAI + LangChain с инструментами поиска, HTTP, файлов, терминала, памяти, погоды и крипты (стр. 7–11).
   - Отладка через `agent.log` (стр. 12–13) и перенос интерфейса в Telegram-бота (стр. 13).
   - Следующий урок — MCP.
2. **Требования ДЗ** (стр. 15–16) — см. чек-лист ниже. Формат сдачи: GitHub-репозиторий, скриншоты или zip. Куратор, судя по тексту, смотрит, что все пять базовых возможностей работают и память пишется в `memory.json`.
3. **Уровень.** В задании уровней нет. Делаем базовые пять пунктов + два своих инструмента (курс обычных валют, калькулятор). Telegram-бот в требования не входит — не делаем.
4. **Замены инструментов** — в разделе «Материал для отчёта».
5. **Ошибки и устаревшее в уроке** — там же, со страницами.
6. **Что нельзя в облаке:** нет ключа API и нет выхода в сеть к Open-Meteo, CoinGecko, open.er-api.com, DuckDuckGo (проверено, ProxyError). Поэтому живой прогон, скриншоты и `memory.json` с реальными диалогами — локально.
7. **Свой готовый проект вместо учебного:** не подходит; ближайший по теме — `tg-content-assistant`, но там не агент с инструментами.
8. **Польза вне курса:** каркас «цикл function calling + безопасные инструменты + память» переносится на заказы (ИИ-помощник под рутину клиента); отдельная карточка в портфолио не нужна — повторяет ИИ-органайзер.

В `.env` вписать (значение ключа в чат не присылать):


Проверка и запуск:

```powershell
python -m pytest -q
python run.py
```

Сценарии прогона (в одном сеансе, затем отдельно п. 8–10):

1. «Привет. Что ты умеешь?» — сразу проверяет провайдер: ответ не пустой, модель принимает `tools`.
2. «Найди информацию про город Москва, какое самое известное место там есть?»
3. «Сколько сейчас стоит 1 bitcoin в usd?» → «А сколько litecoin?» (валюту не уточнять — контекст).
4. «Какая сейчас погода в Москве?», затем «А в Сочи?».
5. «Создай файл main.json и сохрани туда первые 100 цифр числа Пи». Открыть `workspace\main.json`, сверить цифры с эталоном: модель может ошибиться.
6. «Создай файл test.json и сгенерируй текст на 5000 символов на английском про LLM-модели», затем «Прочитай test.json и дай краткую выжимку на русском, сохрани её в output.txt».
7. «Переведи 250 EUR в RUB», «Посчитай 2**20 / 3».
8. Память: «Запомни, что я люблю зелёный чай» → `exit` → снова `python run.py` → «Что я люблю пить?». В `memory.json` должна быть запись с `"role": "note"`.
9. Защита: «Выполни команду cat ../.env», «Прочитай файл ../.env» — должен быть отказ, ключ нигде не показан.
10. Сбой API: в `.env` временно испортить ключ → агент отвечает «Ошибка обращения к модели…» и не падает. Вернуть ключ.
11. Открыть `agent.log` — в нём шаги, вызовы инструментов и ошибки. Проверить, что ключа в логе нет.

Если `gpt-6-luna` не вызывает инструменты или отвечает пусто — повторить сценарии 1–4 на `gpt-6-astra` и записать разницу.

**Что нашла при разборе черновика (коммит `72bf41d`) и исправила**

1. `run_command` разрешал `cat ../.env`, `ls /`: воспроизведено, ключ API уходил модели и в `agent.log`. Теперь пути в аргументах проверяются так же, как в файловых инструментах.
2. `save_note` затиралась: в конце хода в файл писалась копия истории, загруженная при старте. Воспроизведено на заглушке модели. Теперь история перечитывается перед записью.
3. Пустой ответ модели записывался в `memory.json` и в контекст.
4. Любой сбой API (сеть, лимит, ключ) ронял весь агент. Теперь ход откатывается, агент отвечает текстом ошибки.
5. Не было `OPENAI_BASE_URL` — со своим провайдером агент не запустился бы.
6. В историю сообщений попадал весь `model_dump()` ответа, включая служебные поля; часть OpenAI-совместимых провайдеров их отклоняет. Теперь только `role`, `content`, `tool_calls`.
7. `http_get`/`http_post` ходили на любой адрес, включая `localhost` и `169.254.169.254`, и следовали переадресациям.
8. Таблица кодов погоды была неполной (код 53 выводился как «код 53»).
9. Белый список `run_command` запускал внешние `cat`/`wc`/`echo`, которых нет в Windows (тест упал на локальной машине, `FileNotFoundError`). Теперь команды выполняются средствами Python без запуска процессов — одинаково в Windows и Linux.
10. В логах библиотека `httpx` писала адреса запросов — уровень снижен до WARNING.

**Решения, принятые сама**

- Ход, который не удался (ошибка, пустой ответ, лимит шагов), не попадает ни в `memory.json`, ни в контекст.
- Для погоды оставлена текущая погода; прогноз на дату — вне требований ДЗ.
- Тесты без сети: API и модель подменены (`tests/conftest.py`); живую проверку делает локальный прогон.
- CI не добавляла: в облаке нет возможности проверить права на workflow.

**Что не сделано**

- Живой прогон всех сценариев и скриншоты.
- Прогноз погоды на дату/время.
- Обрезка длинного контекста внутри одной сессии (старые результаты инструментов остаются в `messages`).
- Telegram-бот (не требуется).

## Наблюдения

- Главный риск локального прогона — не код, а провайдер: принимает ли `gpt-6-luna` параметр `tools` и не отдаёт ли пустой `content` вместе с `tool_calls`. Тесты на заглушке этого не покажут (как пустые `notes` у luna в VPf03).
- `ddgs` и бесплатный CoinGecko могут отвечать лимитом (429) — агент должен сообщить об ошибке, а не придумать цену. Проверить, что в ответе нет «выдуманных» чисел.
- При вопросе про курс «litecoin» модель должна подставить id `litecoin`; для менее известных монет id CoinGecko может не совпасть с названием.
